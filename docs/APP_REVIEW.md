## Test Information → Beta App Description

```
everylove is a companion app where you design a fictional character and they take the lead in the relationship: they text you first, remember what you tell them, keep their own daily life going in a small in-app "phone" (messages, notes, calendar, timeline posts), and can meet you for outings or a voice call.

All characters are fictional and AI-generated. Conversations, posts and notes are written by a language model based on the character you create or match with. Nothing in the app is a real person.

This beta focuses on the first hour: matching with a character, chatting until they ask to exchange contacts, unlocking the home screen, and the character reaching out on their own.
```

## Test Information → What to Test (per build)

```
Please try, in order:
1. Onboarding → pick a language → swipe right on a character → chat until the heart meter fills and they exchange contacts.
2. Sign in when prompted (Sign in with Apple, or the email + password below).
3. Home screen: open Message, wait for / trigger the character's first message, reply a few times.
4. Outing: pick a place and have a scene with the character. Try taking a photo there.
5. Phone: from a chat, tap "+" → look at their phone (lock screen; ask them for the passcode).
6. X (timeline): like and comment on a post.
7. Create: build your own character from a description or the form.

Known limitations in this beta: subscription tiers in Settings are a placeholder (no payments are collected); voice calls need a network connection and may take a few seconds per turn; some Korean and Japanese copy is still first-draft.
```

## App Review Information → Notes

```
ABOUT THE APP
everylove is a fictional-character companion app. Users create or match with an AI character who then leads the relationship: sends the first message, remembers details, posts on an in-app timeline, and can meet the user in text-based "outing" scenes or a voice call. Every character is fictional and generated by a language model; the app does not use, depict, or impersonate real people.

SIGN-IN
Sign in is optional at first. The app asks the user to sign in the first time a character is added to their contacts (so their data can be backed up), and it can also be reached from the first onboarding screen ("Sign in") or from Settings → Account.
Supported methods: Sign in with Apple, or email. For review, use the test account below — entering this email switches the form to an email + password login:
  Email: test@kotoko.ai
  Password: (see Sign-in required field)
The test account has no saved data; the app will simply upload the reviewer's local progress.

CONTENT & SAFETY
- Tone is romantic but non-explicit (comparable to a teen-rated romance novel); the model is instructed to stay within that line and this cannot be overridden by user-created characters.
- If a user's message indicates distress or crisis, the app leaves the roleplay and responds in a supportive mode with crisis-line information for the user's language/region.
- Characters are constrained from manipulative behavior (no guilt-tripping, no spamming, no pressuring the user to stay).
- Real people: character creation refuses uploads described as real-person photos and blocks names of real public figures and well-known copyrighted characters. The app never comments on other real people appearing in content the user shares.
- Age rating 17+ (romantic themes, user-generated content).

USER-GENERATED CONTENT
Users can create characters and optionally make them public so other users can match with them. Public characters are filtered by the blocklist above and carry a "from another player" label. Users can also create "worlds" (settings) that characters live in and share them the same way.

PERMISSIONS (all optional)
- Location: only to show real local weather in the app; coordinates stay on the device.
- Microphone: only during a voice call or when recording a voice message.
- Photos / Camera: to add a picture in chat or to give a created character an image.
- Notifications: local notifications only, for the character's outgoing messages; the user sets quiet hours in Settings (default 23:00–08:00).
- Share extension: lets the user share text, a link, or an image from another app to a character.

PAYMENTS
No in-app purchases are active in this build. The "plan" section in Settings is a placeholder that changes a local slot limit for testing; nothing is charged.

NETWORK
Chat, voice and image generation call third-party AI providers through our own server. Users may optionally enter their own API key in a developer section; none is shipped in the build.
```

## Before public link — things a reviewer may ask about

- **Guideline 1.2 (UGC)**: Apple expects filtering, a way to report objectionable content, a way to block abusive users, and published contact info. Filtering exists; **report / block do not yet** (OPEN_QUESTIONS #7 moderation). If Beta App Review pushes back, the quickest fix is a "Report" action on public characters / worlds and a support email in the app.
- **Guideline 5.1.1 (data)**: privacy policy must mention: account (Apple ID / email), chat content sent to AI providers, cloud backup on Supabase, location kept on device, no sale of data, deletion via Settings → Account → Delete cloud data.
- **Guideline 3.1.1**: the placeholder plan switcher is fine only while it charges nothing; once real subscriptions ship they must be StoreKit IAP.
