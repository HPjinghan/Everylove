## C. 对话

### C1 · 对话模式与 prompt 规范
- **现行**：
  - **五种模式**各自独立 prompt，只共用红线与输出格式：初识（交友试聊 / 自创暧昧期）、亲密（羁绊会话）、外出、通话、X 回帖 post（D-178：走回合管线，亲密背景 + 回帖写法，一句）。系统 prompt 按分段表装配（见 A3）；**稳定段在前、动态段在后**（D-175），稳定段逐轮一字不变，作 prompt 缓存前缀；只在某些情况出现的段用 `when(ctx)` 过滤、不注册影子段（D-189）。
  - **指令文本用英语**（D-142：模型对英文指令更稳）：分段、舞台提示、卡片与语音 / 照片进上下文的文字、时间与天气行都是英语，段标题用 `[Who you are]` 式方括号；只有角色内容、输出语言行、危机热线按语言切；暗号 token 与记忆前缀保持中文；任务类 prompt（记忆 / 看图 / 解析 / 身边的人 / 发帖）仍中文。
  - **TA 以真人自居**（D-154）：第一行「You are X — a real person living your own life; none of this is a performance」，全文不出现扮演 / 虚构 / app，暗号说明写 as yourself；危机时「放下一切认真回应」而非出戏（处理不变：认真回应 + 当地热线）。红线 1 指不捏具体真人，与此不冲突。任务类里 TA 自己开口的（X 回帖 / 发帖 / 评论区、身边的人、TA 的日程）同样真人自居（D-168）；助手类任务（记忆、约定识别、周薪）保留「虚构角色」描述。
  - **初识**：陌生人分寸，不自来熟、一次最多一个问句、不推进关系；情境「刚在交友软件上配对」（自创暧昧期 = 说不清的熟悉感，有共同记忆则像重逢）；只给资料卡级信息。**亲密**：关系状态、声音样本、时间感、生日、记忆、阶段分寸六档、怎么爱她、秘密、主动强度、手机密码、红包规则。**通话**：亲密背景 + 一次一两句、只说出口的话。**外出**独享（）现场描写、不分条、TA 先开口。
  - **像个人一样说话**（D-141 / D-151，`TALK_MANNER`，四种对话共用）：**长度跟着她**（她随口一句 TA 一两句甚至一个字，她一大段 TA 可到三四句）；跟着她的劲儿、听潜台词不分析她；只回这一条、可以漏答、不刨根问底、最多一个问句；有自己看法、会接梗损回去；句式不重复、话题聊完就换；语气词与真人小瑕疵偶尔用（小瑕疵每 5–8 句最多一次）；无客服腔 / AI 话术黑名单 / 安慰套话 / 煽情，不每条叮嘱收尾；emoji 只在她先用才偶尔跟。真人回复约三分之一该一两个字。
  - **恋爱类型话术包**（D-151）：14 种恋爱类型各有会流露的情绪 / 口头习惯 / 不会做的事，进四种对话；病娇再写一次行为健康底线。
  - **一条规则只说一次**（D-152）：通用说话方式只在 `TALK_MANNER`，各模式段只留独有的；有长度守卫（亲密满字段 ≤7500 / 初识种子 ≤5600 / 通话 ≤6500 / post ≤5200 字符），加规则先想能否并进已有一条，超线就砍别的。
  - **行为框架分拣**（D-153）：写进 prompt 的只有模型每轮真能照做的说话方式；需要记忆、时间、趋势或状态的做成系统——主动找话题 = TA 主动找她（D7）；话题不重复 = 主动消息舞台提示带最近三条主动消息；她回复变短 = 按长度趋势算（最近 3 条平均 ≤ 之前的 45%、且第 4 条还正常），只出一轮「留意一下」；主动转账 / 点外卖别每次都用 = 三道门 + 10 条冷却（D-130）；不做「禁止冷场」（冷场由时间解决：TA 隔一阵按钟带新话题回来）。
  - **一两个字的回复**（D-144，`features/brevity.ts`）：她这条 ≤10 字（英文 ≤3 词）且没问号 → 末尾加「同样短地回」；中等长度（≤60 字）约 25% 抽到「几个字就够」；问句 / 长段不加。
  - **纯打字感**：聊天两模式禁（）动作，兜底剥离全角（）、`*动作*` 与不含字母数字的半角括号。**末尾句号前端去掉**（D-145）：每条气泡与台词只去最后一个「。」/「.」，通话除外。
  - **客户端拆气泡**（只在亲密模式；初识 / 外出 / 通话一条不拆）：先按空行、再按中日文之间的空格（D-159：每个空格一条，韩语与拉丁词 / 数字旁的空格不断）、再按标点。**两种节奏按人设**（D-155）：整句（句末标点拆，默认最多两条）/ 连发（句末标点 + 逗号顿号分号都断，一个字的碎片并回前条）；谁连发 = 角色自设 > 恋爱类型（小狗系年下 / 阳光直球 / 青梅竹马 / 毒舌竹马 / 傲娇连发，其余整句）> 原型（sharp 连发），创造高级区可选跟着人设 / 整句 / 连发。**整句的长回复按长度拆**（D-213）：约每 36 字（中日韩一字 1、拉丁 0.5）一条，句子还长在逗号处拆。上限六条（D-212），**超过上限均匀分**，相邻段按长度并、不丢字不改顺序。
  - **输出语言按界面语言**；「她」固定指用户，非女生用户注明只是指令写法。红线段：尺度、行为健康、不评价真人（含照片里的人）、危机热线按市场（中国 12356 / 美国 988 / 日本 よりそい・いのちの電話）。
  - **回复节奏**（D-146）：每条气泡上屏前有按字数算的「正在输入」；**首字延迟**（D-200）：第一条扣掉模型已花的时间；**不做流式**——产品是整条上屏的打字感，流式与拆气泡 / 剥暗号 / 去句号冲突。

### C4 · 打电话
- **现行**：拨号 → TA 接起先开口 → 播完自动听她说 → TA 回 → 再听；免提 / 听筒即时切换。双方的话都进羁绊会话并计 XP，挂断留「📞 m:ss」并提取记忆。计时与扣分钟见 D4。
  - **实时**（D-232，0.3.0 起的包）：她说话时 iPhone 本机边听边认（字当场出在字幕里，有本机语音包就不上网），停顿约 0.75 秒算说完；TA 的回话不开思考、**边出字边合成**（模型每吐出一整句就送去合成，暗号与（）不念；后面的句子在前一句播的时候就在合成）；边合成边播（PCM 流，代理 `eleven.tts.stream`，D-241），不等整段合成完。暗号、记忆、落会话仍等整段回完。**通话通道**（D-238，0.4.0 起的包，`modules/live-call`）：听和播在同一台音频引擎里，开着系统通话模式的 voice processing（回声消除 + 降噪）——引擎知道自己在放 TA 的声音，从麦克风里减掉，所以 TA 说话时也一直在听，她插话（再按字面滤一遍回声）或点 TA 的头像，TA 就停下来听她；免提走扬声器覆盖。为什么自己写：识别（expo-speech-recognition）与播放（react-native-audio-api）是两个库各开一台引擎，同时跑会互相触发重启（TestFlight 实测音量条来回跳、麦克风收不到声），也没有回声消除；改识别库里现成的引擎不如照它写一台只管通话的。**0.3.0 的包**没有通道，半双工（D-237）：TA 说话时不听、只能点头像打断，她说话时播放器挂起，音频会话只归识别库管。实测（经代理，从欧洲连新加坡的库）：改前一轮约 14～16 秒；改后模型首句约 2 秒、Fish 首音约 0.7～1.3 秒，加上断句，一轮约 4 秒（换 ElevenLabs 后待重测）。
  - **管线式**（D-077）：没有这两个原生模块的包（Expo Go、网页、0.3.0 之前的包）、或这台手机认不了这门语言时用——录整段（音量计断句，一句最长 30 秒，可手动断句）→ 识别 → 回 → 合成整段 → 播。
  - **为什么不接端到端语音模型**（D-232，Harper 拍板，#26 了结）：电话里 TA 要还是同一把声线、同一套 Claude 人设与记忆；端到端模型（OpenAI Realtime / 百度）换声音换脑子，贵 10 倍以上。
  - **代理为实时减负**：本地验 JWT；次数与记账并行问；流式的模型与合成请求和闸门同时发出去，闸门不放行就掐掉上游；流式的账在流完之后记。
  - **未做**：TA 主动来电、铃声与接听动画。还能压的：网关比直连 Anthropic 首字慢 0.3～0.5 秒（D-216 为并发留着网关）。
- **代码**：`app/call/[characterId].tsx`、`lib/call.ts`、`lib/live-voice.ts`、`modules/live-call`；代理 `supabase/functions/ai`（`fish.tts.stream`、`anthropic.messages` 的 `stream`）

### G2 · 账号、登录墙、云同步
- **现行**：

  - 对账规则：云端无备份 → 传本机；这台手机没和这个账号对过账（或是别的账号）→ 本机不许覆盖云端：本机空（没 onboarding，或无羁绊、无自创角色、相册与记事本都空；试聊不算）静默拉云端，本机有关系则登录界面问「接回云端的 / 用本机覆盖云端」；同步过的手机 → 本机脏就推（正在用的设备赢，D-057），云端更新就拉。

## H. 文案、语言与设计

### H1 · 文案规范
- **现行**：
  - 界面提示只描述内容或情绪，不解释机制、不指路、不预告交互方式；保留三类：红线与政策告知、隐私与数据说明、商业信息。表单提示只定义填什么。
  - 措辞：用户可见文案一律不出现「领养」（改小火苗 + 热度，「领养」只作机制词）；缔结 = 交换联系方式；「领回家」→「加好友」；通用代词「TA」；TA 不当客服。
  - 开发者话术只在开发构建出现（D-180）；「AI 不可用」一律 `alertAiUnavailable()`，用户只看到「现在联系不上 TA。」；失败原因（模型 / 生图 / 拨号）只在开发构建露出，用户只看到一句情绪话，不弹说破生成的提示（D-223）。
  - 英文一样东西只一个名字（D-223）：Messages、Their Phone（不和 Phone 撞）、Dating、Coins、RingBit / RB、Fortune、unsent、Snap them、通话「说完了」= I'm done、分享 Send to…；单复数与计量各给一条键。

### H3 · 设计系统与主题
- **现行**：
  - **一部有自己特色的小手机**（D-231）：尽可能像一部手机，但不像任何一个具体型号（不照搬某款手机的系统色、字体、毛玻璃）。App 里面是手机 App 的样子——浅灰底、白色分组卡片、细分隔线、白色顶栏、胶囊 chip、浅灰轨道里白块的分段控件；强调色是我们自己的品牌粉，危险用红；聊天保留涂鸦聊天纸、对方白气泡 / 自己粉气泡、胶囊输入框。为什么：要「更像一个被用户自己设置了甜蜜壁纸的手机」——甜的是壁纸，手机本身要像真的。
  - 原纸面设计系统（粉底 + 菱格暗纹，`design/` 下的 Claude Design 原文，D-083 / D-100）留作壁纸之一，不再是界面风格；墨色粗描边退役。Fredoka 只管数字与拉丁标签（这部小手机自己的字），中文一律系统字体。阴影只给浮起来的东西两档（图块 / 小组件 / 分段选中块一档，通知横幅与底部卡一档），普通卡片按钮不投影。palette 外只允许通话深底、TA 记事本米色与桌面图块各自的 App 色。
  - 纪律（CLAUDE.md §11-4）：界面只引 design token，不手写 hex / 圆角 / 阴影 / 字号（字号只从统一阶梯取，D-199；阴影只用 `Elevation`）；卡片 / 按钮 / 选项 / 表单 / 遮罩用对应 primitive。按钮与顶栏动作自带连点冷却（D-121）。全项目不用系统 `Alert.alert`，一律 `showAlert`（底部通知卡 / 确认卡 / 动作卡，D-160 / D-164）；小按钮补足 44pt 点击区、图标按钮带读屏标签（D-198）。
  - 每个 App 像它自己（D-206）：靠一个标志性版式给模块拟真感——X 推文串线 + 紧凑时间、外卖左店右菜 + 墨色购物车条 + 四段配送进度、幸运签签纸、TA 的手机 Dock + 角色色钱包卡面；纯拉丁 App 名的标题走 Fredoka。
  - **像它那一类 App**（D-231）：第三方类 App 里面的强调色跟它桌面图块一个颜色——交友珊瑚粉（大圆角浮卡 + 两颗圆按钮）、X 黑白（白底时间线、圆头像、黑色发送）、外卖黄（黄底黑字的加号与下单、墨色胶囊购物车）、幸运签紫；系统类各留一处手机感——设置每个分区首行一枚小彩色图标、可点的行带「›」，日历选中与今天用红，记事本用黄，钱包余额是一张深色卡面。TA 手机上的图块用她桌面同一个 App 的颜色。配对成功与缔结仪式铺她的桌面壁纸（这一刻是手机本身在庆祝）；登录页不铺暗纹。
  - 手感层（D-207）：震动统一从 `lib/haptics.ts` 叫，新动效一律 Reanimated；新落下的消息淡入、「正在输入」跳点、好奇条平滑推进，滑卡 / 点赞 / 下单 / 抽签各有一下反馈。
  - 仪式时刻（D-208）：情绪峰值单独演一下但不破纸面规范——缔结时立绘像拍立得显影（只剩两行字，不念她自己起的昵称，D-223）；她正看着时羁绊升级 → 全屏立绘 + 新等级。
  - 等待态（D-209）：等生图的地方画一张正在显影的相纸，字一句句往下走，不转圈、不报进度或秒数。
  - 图标、字号与读屏（D-229）：界面不拿彩色 emoji 当图标（天气、空状态、按钮、锁），一律单色 MingCute；空状态画一张还没洗出东西的空相纸。地点与店铺的 emoji 是内容，不在此列。系统开大字号时正文跟着放大不设限，尺寸固定的控件（按钮 / 分段 / chip / 顶栏 / 桌面图块 / 角标）最多 1.3 倍、时钟与温度 1.1 倍，免得撑破版式；10 号字只给角标，说明与手写字至少 12。设置这类长列表行间用浅线、卡片边框仍是墨线。桌面图块、通用按钮 / chip / 分段 / 动作卡带读屏角色与标签。
